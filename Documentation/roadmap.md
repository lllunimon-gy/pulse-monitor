# Pulse 诊断实验室路线图

目标：以低开销采集可解释的现场，用可复现实验验证检测边界和优化效果。
不把代理指标、时间相关性或会话未完成标记当成根因。

## 本轮实现顺序

1. 检测可靠性：已结束区间、有界历史、结束时间、发现快照、交付背压、运行代次。
2. 事件现场：会话和页面上下文、父子 Span/signpost、资源趋势、字节受限存储与诊断包。
3. 性能与稳定性：刷新节奏代理指标、业务交互/启动区间、内存趋势、对象存活检查、上次会话证据。
4. 系统诊断：MetricKit 原始载荷、类型标记、去重、独立存储、结构摘要和兼容边界。
5. 示例实验室：计算/等待、图片解码、列表更新、内存保留、MainActor 短任务、慢消费者、详情和导出。
6. 验证：确定性单元测试、实际 RunLoop 测试、macOS 和 iOS Simulator 构建、真机实验协议。

## 交付门槛

- 新增状态、窗口和容量语义必须有边界测试。
- 公共模型明确来源、计量口径和可用性，不输出推测的 Crash/OOM 原因。
- 每个内存集合和磁盘档案均有容量策略；调用方提供的标签需要脱敏。
- GitHub CI 的测试和示例构建通过后交付；真机性能结果仅在实际测量后填写。

## 0.2 实现状态

上述六阶段的首版代码、实验界面、导出、文档和自动化检查均已加入。
检测器仍保留已说明的 RunLoop 代理指标边界；系统诊断层当前提供载荷接收、
去重和结构摘要，不包含完整符号化。启动以业务 Span 和系统原始载荷分别观测。
这是一套可验证的本地诊断基础，真机基准、生产接入和系统覆盖测试按下表继续积累。

## 后续需要设备/业务环境完成的验收

- 固定设备、Release 构建，关闭监控/不同采样间隔各重复至少五次。
- 对照 Instruments 的 Time Profiler、Hangs、Animation Hitches、Allocations 和 Points of Interest。
- 验证低内存、低存储、锁屏、文件保护、系统挂起、多窗口和可变刷新率。
- 对接业务上传和符号化服务属于独立部署工作；本库提供本地诊断包，不默认传输数据。
