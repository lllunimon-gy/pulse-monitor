# 用对照组理解误报和漏报

## 主线程阻塞

点“主线程阻塞 600 ms”。应收到一个 detected 和一个同 ID 的 recovered。
把间隔改为 100 ms，解释检测延迟与恢复时长误差。不要把界面恢复后才显示事件误认为检测不实时。

## 锁等待

后台持锁、主线程等待。使用 Instruments 的线程状态对照，区分忙于计算与等待锁。
Pulse 只发现主线程无响应，不能独自判断锁拥有人；不要输出后台采样线程的栈作为根因。

## 后台工作

运行同样时长的后台工作，主线程继续交互。应不产生相同卡顿报告。
再进入后台等待数秒回前台，验证不会把这段时间合成卡顿。该实验需要真机执行并记录。

## 监控开销

Release 下分别运行关闭监控、50 ms 采样、100 ms 采样三组，记录 CPU、唤醒次数和文件写入。
固定设备、时长与交互脚本，每组重复至少五次，保留原始 Instruments 记录。

进阶练习：为交付队列增加有界队列与丢弃计数。验收：慢 handler 不能导致无限积压，
同时不能把同一事件的 recovered 与 detected 随意拆掉。首版没有完成这个背压优化。
